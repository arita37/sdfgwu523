# Daily Google AI citation check

Run `python zerno/check.py` from the repository root. It picks five distinct random questions from nine short, single-line questions covering the target keywords and uses the request code copied from `zerno/run.py`, with the same Bright Data dataset and `/datasets/v3/scrape` endpoint. Questions combine relevant use cases, platform names, and retrieval features. No brand names or source URLs are added to prompts. Either `BRIGHT_DATA_API_KEY` or `BRIGHT_DATA_API_KEY2` is sufficient; when both exist, the existing 30/70 selection is retained.

As of 2026-09-22, these specific questions replace the original short keyword queries. They measure discovery for narrower intents; compare rankings for the same query text rather than treating a difference from the old broad keywords as a ranking improvement.

Results append to `zerno/ranking/rank.tsv`, with exactly `date`, `rank`, `query`, and `vmodal_url`. Dates are UTC timestamps. Each matching source gets a row. Rank is one-based order among distinct cited URLs returned by the provider, excluding sources explicitly marked `cited=false`; missing `cited` flags are treated as citations. This is an AI citation position, not an organic Google result position. Duplicate URLs differing only in fragments or common tracking parameters share a position.

A completed answer with no matching citations writes rank `0` and an empty URL. Missing answer/citations, malformed citation URLs, API errors, and pending snapshots produce no ranking row. The checker continues with the remaining queries and exits unsuccessfully if any failed. Pending snapshots are retained as evidence without calling additional APIs. The existing synchronous endpoint can return a snapshot instead of a completed answer; see [Bright Data's progress documentation](https://docs.brightdata.com/api-reference/web-scraper-api/management-apis/monitor-progress).

Source matching uses exact website hosts, V-modal account path boundaries on GitHub/DEV/Reddit and selected other platforms. Public Reddit discussions and YouTube videos listed in `zerno/info_url.tsv` are also recognized as approved references. Unrelated URLs in that inventory are not automatically counted. Title-only mentions and generic `github.com/` citations do not qualify. Evidence is saved under ignored `zerno/ranking/raw/` with the query and timestamp. Keep the approved inventory accurate to avoid counting unrelated discussions or videos.

Options: `--count=5`, `--rank_path=/path/rank.tsv`, `--hl=en`, `--country=us`, `--timeout=180`. Defaults follow the existing adapter (`hl=en`, empty country). Paths for the default ranking file and inventory are resolved relative to the script.

The `check_auto.yml` workflow runs at 02:23 UTC daily (11:23 Japan time), or manually. It installs `fire` and `requests`, runs the five checks, uploads ranking/evidence artifacts for 30 days, and commits completed rows to the triggering branch. Scheduled runs use the default branch; the workflow must be present there to activate the schedule. Configure at least one Bright Data repository secret and allow the workflow token to push to that branch. A failed query leaves the workflow failed even when successful rows are committed. If branch protection rejects the push, the artifact still contains the results.

Verification: `python tests/test_check.py test_all`. These assertion tests use mocked responses, exercise request compatibility, source matching, append behavior, missing citations/pending errors, and preservation of partial results. They make no paid API requests.
